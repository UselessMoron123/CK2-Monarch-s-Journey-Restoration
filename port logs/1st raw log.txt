possible to make mj in form of dlc or something mod-like?

Yes—but only partly.
Short answer

    On 3.3.3, much of Monarch’s Journey can be packaged in a mod-like installer: payload, localization, interface assets, and scripts. The executable patches still need a guarded patcher because the feature is disabled inside native code.
    On 3.3.5.1, a normal CK2 mod or ordinary DLC package cannot restore the complete feature by itself. The latest executable removed the payload parser, virtual feat-script loader, and much of the MJ frontend controller.
    A hybrid mod plus native loader/plugin is technically possible and is the most realistic route to a latest-version restoration.

What a normal CK2 mod can provide

A mod can likely contain:

    all ruler definitions;
    challenge scripts;
    localization;
    portraits and interface graphics;
    event and decision logic;
    score variables;
    custom notifications;
    an approximation of Bronzeman restrictions;
    an independent menu or in-game window, using CK2’s moddable UI where possible.

This could reproduce the gameplay concept of Monarch’s Journey on 3.3.5.1 without restoring Paradox’s exact internal implementation.

It could also avoid the original required_dlcs payload gate. However, it cannot grant access to mechanics or content belonging to DLC the user does not own.
What a normal mod cannot restore

A conventional CK2 mod cannot ordinarily:

    add arbitrary native C++ controllers to the main menu;
    reconstruct removed CHighlightedRuler objects;
    invoke the removed GameSparks JSON parser;
    feed feats_script into the removed gs_virtual/feat_script path;
    reconnect the original main-menu MJ panel when its controlling code is absent;
    change hardcoded executable checks;
    perfectly reproduce the native feat cache and Bronzeman integration.

A fake .dlc descriptor would not help. CK2 DLC packages are recognized through Steam ownership and native DLC-manager logic; creating an unofficial DLC entry would neither restore removed code nor legitimately unlock official DLC.
Three possible products
1. V9 “restoration mod package”

Target: May 2020 Windows 3.3.3.

Package together:

    normal CK2 mod files where possible;
    gfx\monarchs;
    localization/assets;
    guarded V9 executable patcher;
    apply/check/revert launcher.

This would be easiest to install, but technically remains a mod plus binary patch.
2. Reimplemented MJ mod for 3.3.5.1

Target: latest CK2.

Rebuild the experience using ordinary CK2 scripting:

    select a ruler through decisions, events, or a custom bookmark;
    initialize three challenge variables;
    calculate progress using events and scripted triggers;
    show progress through decisions, character modifiers, events, or a custom in-game window;
    grant Bronze/Silver/Gold through flags and notifications;
    store progress in saves;
    optionally enforce restart/character-switch restrictions through scripting.

Advantages:

    no code injection;
    latest CK2 compatibility;
    easier to add every known ruler;
    maintainable and distributable as an ordinary mod;
    does not depend on dead Paradox services.

Disadvantages:

    not the exact original main-menu panel;
    limited UI and persistence compared with the native implementation;
    some challenges may require approximations;
    unavailable official DLC mechanics remain unavailable.

This is probably the best long-term solution.
3. Native 3.3.5.1 restoration

Target: latest CK2 with the original UI/engine systems.

Build a DLL/native loader that injects replacement data and possibly restores missing controller behavior.

Advantages:

    potentially closest to the original feature;

Why GameSparks mattered

GameSparks itself is not inherently necessary for offline Monarch’s Journey. It was merely Paradox’s delivery system.

In 3.3.3, the chain is approximately:

text

GameSparks interface
  ↓
load local JSON payload
  ↓
parse scheduled_rulers / highlighted_ruler
  ↓
construct native ruler objects
  ↓
extract each ruler's feats_script string
  ↓
load that script as gs_virtual/feat_script
  ↓
build the feat database
  ↓
main-menu MJ panel + Bronzeman + challenge tracking

V9 does not contact GameSparks. However, it reuses the surviving GameSparks-shaped architecture to ingest the local payload.

The important pieces are not networking. They are:

    the JSON parser;
    the native highlighted-ruler object builder;
    the feats_script extractor;
    the virtual-script loader;
    the main-menu MJ controller.

Paradox removed most of those in 3.3.5.1 along with GameSparks. The later executable retains much of the machinery after data ingestion:

    feat tracker;
    feat progress cache;
    Bronzeman fields and autosaving;
    score/reward classes;
    some highlighted-ruler controls;
    special_event save serialization.

The problem is that these surviving systems have little or no data entering them.

So we do not need to resurrect GameSparks networking. We need to replace the useful local-loading work formerly performed by that subsystem.
