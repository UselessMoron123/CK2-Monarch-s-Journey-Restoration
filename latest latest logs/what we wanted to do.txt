x64dbg or WinDbg?

For you, I recommend x64dbg first.
x64dbg

It has a visual interface:

    you can see exactly where the game stopped;
    registers are visible;
    F8 steps one instruction;
    F9 continues;
    F2 enables/disables a breakpoint;
    Ctrl+G jumps to an address.

Use the 64-bit x64dbg, not x32dbg.

The most important addresses are already in the guide, but the main ones are:

text

text

candidate selection
save enumeration

normal Continue caller

A debugger breakpoint is temporary. It is not written into the executable, so merely opening x64dbg and setting breakpoints does not modify the game.
WinDbg

WinDbg is more powerful but less friendly. It is mainly command-driven. It can automatically write breakpoint activity to a log, which is useful when a breakpoint hits repeatedly.

Use WinDbg if:

    x64dbg feels confusing;
    x64dbg cannot attach;
    we need automated logging from the status helper.

text

C:\Users\UZWERG\Desktop\SteamCrusader\CK2game.exe

    Wait for x64dbg to finish loading.
    Press F9.
    If Windows asks about firewall or permissions, allow/confirm it.
    Wait up to 30 seconds.

If CK2 immediately disappears, look at the bottom of x64dbg for an exception such as:

text

INT3
Access violation
DLL initialization failed
0xC0000135
0xC0000005

If you start CK2 through Steam instead, x64dbg may be attached to the launcher or Steam rather than the actual CK2game.exe. In that case:

    Start CK2 normally.
    Start x64dbg.
    Use File → Attach.
    Select the process named CK2game.exe.
    Press F9.
